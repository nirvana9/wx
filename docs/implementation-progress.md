## 审查与验证

独立审查发现 2 项 Important，已在一轮修复中处理：

1. SIGKILL 会遗留含凭据/正文的实际临时快照。重开与本地清理现在在账号锁内移除本进程用户拥有、单链接的普通临时文件；跳过链接和其他所有者的文件。
2. 损坏 JSON 会阻止本地退出清理。`ClearCredentials` 可清除损坏状态；新增 `store.ClearAccount(path)`，在 `Open` 因损坏失败时仍可显式清理。普通 `Open` 继续报告损坏。

回归测试先复现了三个失败：遗留真实临时文件、已打开 Store 无法清理损坏状态、打开失败后无法清理。
修复后这些测试和符号链接隔离测试通过。中断测试杀死的是已把完整数据写入临时文件的实际原子写入子进程。

验证结果：

- `go test -race ./...`、`go vet ./...` 通过。
- wire fuzz 30 秒、357657 次执行通过；wire 模块此后未变。
- Python 16 个测试通过，包括实际原生 CPU replay、来源核对、契约、ELF 映射和采集工具；Node 采集 agent 的二进制布局/关联/入口拒绝测试通过。
- 完整 deb 的 119 处契约字节引用全部匹配，六个挂接入口、单字节常量及 15 项跳表也匹配完整 ELF；三个验证标记仍为 false。
- 完整分析脚本重新运行成功，原有 7 份 JSON 与已提交证据一致；3 份新增 helper 汇编及分派摘录与再生输出一致。此前静态分析未执行样本；本轮仅在 CPU 模拟器中执行指定密码函数，没有启动客户端。

2 项 Minor 暂缓：Go/Python 对缺失或 null JSON 键及验证标记一致性的校验不同；Python 收到数组类型的 representation 时可能抛出 TypeError。
当前仓库契约通过两侧校验且仍被拒绝用于业务操作；该历史通用契约继续拒绝业务启用；新增独立 QR 子集不使用它，完整登录协议接入前需统一严格校验。
另记录 API 策略待办：自定义 Parse 限制大于默认值时，Join 仍受默认限制。
二维码帧与解压已经用真实交换验证；丢确认、扫码状态、过期/取消/重连及在线收发属于未实现任务。

## 实施取舍

- 在原检出之外建立本地工作区；只隔离开发，不创建远程分支。需要改变时可移除本地工作区。
- 技能辅助脚本无法读取，使用手工任务 brief、RED/GREEN 日志和进度账本；代价是需人工核对记录。
- 增加 65536 字段预算，防止小字段放大分配；代价是拒绝极端密集的有效消息。
- Task 5 只依赖 Task 1，因此在二维码恢复期间先完成；协议证据带来的类型调整仍需衔接。
- logout 保留非敏感设备标识，清除账号凭据、联系人和消息状态；标识仍留本地以保持稳定。
- 任务 2 仅交付证据检查与拒绝逻辑；不补猜测值和成功夹具，代价是在线登录继续等待协议恢复。
- 显式清理损坏状态时也丢弃无法可靠恢复的设备标识；代价是后续登录必须生成新设备标识。正常状态仍保留该标识。
- 审查中的在线行为验证保持待办，当前只提交可复核的离线结果；代价是整条登录与收发流程尚未验证。

上述限制是实现状态，不是让用户重新选择协议路线。后续仍按已确认原生方案推进。
