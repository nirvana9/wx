# 微信原生命令行客户端设计

日期：2026-10-11。状态：待用户审阅；本次提交是逆向证据与设计，尚未实现在线客户端。

## 目标和成功标准

用户希望在 `nirvana9/wx` 仓库实现命令行扫码登录、接收消息和主动发送文本消息。用户已选择继续逆向 deb 的原生协议。最终运行时不启动、加载或注入官方客户端，也不依赖 Web 微信登录协议或第三方协议代理。

第一版针对 Linux x86-64、一个个人账号、单个在线进程。用 Go 实现独立客户端；Python 只用于离线逆向工具。支持扫码登录、复用本地会话、实时显示文本消息、按微信内部联系人 ID 手动发送文本、查看同步到的联系人和退出登录。图片、语音、视频、群管理、多账号、自动回复和批量发送不进入第一版。

可用的验收结果是：独立进程拿到真实二维码，手机确认后完成鉴权；在同一在线会话中接收到另一账号发来的文本，并把用户输入的文本发给指定联系人；重启后能正确恢复或明确要求重新扫码。仅能编译、仅能编码 Protobuf、模拟服务端返回成功、运行官方客户端后读取消息，都不能满足此标准。

## 已恢复的证据和实施边界

样本是 `wechat 4.1.13.23`，固定到原仓库提交 `3c16fee9c1d236828871920638596c15e93d5615`。哈希、指令证据和复现命令见 [原生协议逆向进展](../../reverse/native-protocol-progress.md)。

已经定位二维码、扫码确认、手动鉴权、自动鉴权、文本发送和增量同步的原生任务构造代码。已恢复相关 Protobuf 类的解析、计算长度和序列化函数，以及字段编号和部分 wire type。另已定位封包函数和四个 `alts.*` 类型。

尚未证明字段的完整语义、必填约束、每个操作实际采用的加密方式、密钥派生、外层传输格式以及当前服务器的兼容性。实施必须逐项补齐这些证据；不能把 wire 形状直接当成可用 `.proto`，也不能把任务中的 CGI 编号直接当作已验证的包头命令字。

首个在线功能以“获取登录二维码”为协议验证边界：恢复它所需的字段、首包封装和响应解包后，再实现该请求。随后接扫码状态、登录通知解密和首次鉴权。鉴权成立前不实现伪成功的发送命令。

## 用户操作

以下命令描述目标行为，目前不能运行。

```text
wx login                     # 扫码登录，成功后进入在线终端
wx shell                     # 恢复会话并进入在线终端
wx status                    # 显示本地会话状态，不打印凭据
```

在线终端保持一条会话并持续显示收到的消息。用户可输入：

```text
/contacts                    # 已同步的联系人 ID、昵称、备注
/send wxid_example 你好        # 给指定联系人发送文本
/logout                      # 请求服务端退出，并清除本地凭据
/quit                        # 关闭连接，保留可恢复会话
```

采用单进程交互终端，避免为了同时收发而引入后台守护进程和本地 RPC。接收循环在后台 goroutine 中运行，所有连接、任务序号和会话状态归同一个会话对象管理。显示异步消息时重绘输入行，避免覆盖正在输入的文字。

二维码优先以终端图案显示；若响应只给出图像字节，则保存到用户指定位置并输出路径。只在恢复了对应响应字段并验证内容后显示二维码，不把 UUID 或其他任意字符串猜成登录 URL。超时二维码支持重新申请。

联系人参数以内部 ID 为准；不通过昵称猜收件人。发送前检查用户指定 ID 的格式和本地联系人记录；发送结果分为服务端确认、明确失败和结果未知。超时后不自动重发，避免重复消息。第一版只发送用户明确输入的文本。

## 组件和接口

| 组件 | 职责 | 输入与输出 |
|---|---|---|
| `cmd/wx` | 参数、交互终端、退出信号 | 用户输入 → 会话操作；事件 → 终端显示 |
| `internal/session` | 登录状态、单账号生命周期、任务序号 | `Login(ctx)`、`Resume(ctx)`、`SendText(ctx, to, text)`、`Events()`、`Logout(ctx)` |
| `internal/protocol` | 经过验证的消息字段、请求响应和同步命令 | 类型化业务对象 ↔ Protobuf 字节；保留未知字段 |
| `internal/packet` | 包头、压缩、请求和响应封装 | 任务元数据、会话密钥、业务字节 ↔ 网络帧 |
| `internal/cryptox` | 样本证明的密钥交换和加解密 | 显式算法参数与密钥材料 → 结果或校验错误 |
| `internal/transport` | 连接、读写、心跳、取消和重连 | 网络帧 ↔ 按任务匹配的响应和服务端通知 |
| `internal/store` | 会话、联系人、同步游标 | 原子持久化及读取；不参与网络协议 |

协议模块不引用终端代码。传输层不解析联系人或聊天文本。加密层不自行选择业务策略，由经过恢复的包头和任务参数决定算法。

Go 版本在实施时根据官方稳定版本和本地工具链确定并写入 `go.mod`。依赖只为二维码显示、终端输入和确有必要的密码算法添加；先使用标准库。每一个可运行网络请求必须有对应的字段和封包证据。

## 状态、同步和错误处理

状态为：未登录 → 二维码已申请 → 等待扫码/确认 → 首次鉴权 → 已登录。已登录可主动退出或进入断线恢复；自动鉴权明确失效时回到扫码登录。服务端状态枚举、登录通知中的凭据字段及失效错误码由解析器和处理函数证据恢复，不能先写死猜测值。

已登录后完成必要的初始化同步，再运行增量同步。服务端通知和心跳触发同步任务；从恢复的 `CmdList` 分派消息、联系人和游标更新。处理完一个有效同步批次后，将可显示的消息、联系人变更和新的同步游标一起原子写入。重连从上次持久化游标继续；重复消息按服务端消息 ID 去重。没有足够字段证据时不猜消息类型或发送者。

连接中断采用有上限的退避重连；鉴权失败、二维码过期和不可解析包分别显示清楚的错误。解析器限制帧长度和递归深度，拒绝截断、异常长度与认证校验失败的数据。用户取消必须停止接收、轮询、心跳和重连，并关闭连接。

## 本地数据和日志

会话默认存到 `${XDG_STATE_HOME:-$HOME/.local/state}/wx-native/`，目录权限 `0700`，凭据文件 `0600`，写入采用临时文件加原子替换。账号在线期间持有进程锁；第二个进程显示账号已被占用，不复用同一会话同时鉴权。设备标识在本地生成并稳定保存，具体格式由原生协议证据确定。

持久化只包含恢复会话、同步和联系人所需的数据。默认不记录聊天历史。日志不输出二维码凭据、私钥、会话密钥、完整包体或消息正文。用于研究的脱敏抓包只能存到 git 忽略的位置。`/logout` 在服务端请求失败时也清除本地凭据，并告知远端退出尚未确认；`/quit` 保留凭据。

## 协议恢复和验证次序

1. **二维码请求**：沿 `0x77be9a0` 的对象写入核对字段语义；检查 `0x77ece40` 任务类及其封包调用，确定首包参数、包头和响应解密路径。
2. **登录和鉴权**：跟踪 `0x77c2f40`、`0x77c7f00` 和 `0x77d8d20`，恢复登录通知、两类鉴权数据、响应中的会话材料与设备参数。定位失败和过期状态。
3. **封包和传输**：继续分析 `PackMMPkg`、`PackWxPkg`、`UnPackWxPkg` 和 `__EncodePackBuffer`，判明各请求选用的路径及外层网络帧；按有证据的算法建立正反向数据样本。
4. **收发文本**：恢复 `MicroMsgRequestNew` 的字段语义、客户端消息 ID 和发送确认；恢复初始化同步、`CmdItem` 消息命令、联系人更新及同步游标。随后连接到在线终端。

这四项是协议依赖关系，不是对尚未恢复协议的完成承诺。若静态证据不足，需要补充针对性反编译或经过脱敏的请求/响应样本；在证据不足的地方明确返回错误。

离线验证包括固定样本哈希、函数/虚表关系、字段编号与 wire type、封包与解包的已知字节样本，以及截断和认证失败情况。连通性测试只能证明网络可达，不能证明协议正确。端到端验证需用户在自己的手机确认登录，并用明确指定的联系人测试；在此之前文档必须标注未实测。公开仓库不放账号凭据或含真实消息的测试夹具。
